# ADR-0011：完整历史与显式 cut-over 迁移策略

> 状态：Accepted
>
> 日期：2026-09-02
>
> 决策者：项目所有者
>
> 授权：项目所有者在 M0 实现提示中明确接受同时支持完整历史与显式 cut-over、逐账户/组合选择且无安全默认值，并授权本 ADR 直接设为 Accepted。
>
> 关联规则/里程碑：M0、MIG-001 至 MIG-006

## 背景

源工作簿可能存在早于账户期初日的证券交易。自动选取一种全局迁移方式会重复计算现金、丢失交易腿或无法解释历史业绩。迁移必须在不修改真实 Excel 的前提下先进入 staging，并对每个账户、组合和标的闭环。

## 决策驱动因素

- 现金、数量、成本和历史业绩没有重复或缺腿
- 历史资料完整度不同的账户均可安全迁移
- 任何猜测在提交前显式暴露给用户
- 失败不覆盖唯一有效账本

## 方案

### 方案 A：只允许完整历史

审计最完整，但早期现金或交易资料缺失时无法闭环。

### 方案 B：只允许统一 cut-over

实现简单，但会丢失可用历史，且难以保留零持仓历史业绩和组合级费用。

### 方案 C：逐账户/组合选择完整历史或显式 cut-over

复杂度较高，但能在证据允许时保留历史，并在证据不足时建立可解释期初桥。

## 决策

接受方案 C，并且没有默认策略：

- 每个现金账户和组合都必须在 dry-run 中显式选择 `full_history` 或 `explicit_cutover`；未选择返回 `MIGRATION_POLICY_REQUIRED`，不得提交。
- `full_history` 导入全部可验证业务事件。最早现金余额/调整必须与全部证券现金腿闭环，不能再过账包含这些影响的期初余额。
- `explicit_cutover` 中 cut-over 前行只作为迁移证据，不生成 posting。cut-over 日创建 `OpeningBalance`、逐 `(portfolio, instrument)` 的 `OpeningPosition`，以及分开保存已实现交易盈亏、净股息、标的级/组合级独立费用的 `OpeningPerformance`。
- 零数量但有历史业绩的头寸必须保留；组合级费用使用 `instrument_id=null`，不得静默摊派。
- 同一证券事件的现金腿、数量腿和费用腿必须采用同一策略；禁止只迁移其中一部分。cut-over 前事件与已经包含其影响的期初值不得同时过账。
- staging 保存源文件哈希、导入器/schema 版本、工作表、行号、原始文本、公式文本、缓存值和内容哈希。公式只作证据，应用从规范输入重新计算。
- 只有同一字节文件、同一导入器/schema 和同一目标 dry-run 的重跑要求幂等。修改或另存文件是新的迁移候选，不能增量 merge 到已过账账本。
- 对账必须逐账户、组合和标的证明现金、数量、carrying cost、已实现交易盈亏、净股息、独立费用、净资产和支出双口径桥；任一无法解释即阻断。
- 用户确认后在新候选数据库单 transaction 提交、重建投影、复核、创建并验证备份，最后原子切换。任何失败保留原活库。

## 后果

- 正面影响：资料完整的范围保留全历史，资料不全的范围有明确且可审计的期初桥。
- 负面影响：迁移 UI、问题清单和对账报告需要按账户/组合管理策略，不能一键猜测。
- 数据迁移影响：OpeningBalance/Position/Performance 成为正式源事件；cut-over 前证据只保留在 staging/报告。
- 测试与运维影响：必须分别演练两种策略、混用阻断、零持仓业绩、失败回滚、幂等和候选库切换。

## 反转条件

若未来新模板能够证明所有历史完整，可在特定导入器中推荐 `full_history`，但仍需展示证据并由用户确认。不得新增静默默认或对已过账账本做修改文件增量 merge。
