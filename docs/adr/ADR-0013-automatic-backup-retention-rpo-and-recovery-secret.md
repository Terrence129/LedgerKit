# ADR-0013：自动备份保留、设备丢失 RPO 与恢复密钥

> 状态：Accepted
>
> 日期：2026-09-03
>
> 决策者：项目所有者
>
> 授权：任务 13 明确要求完成并接受本 ADR，并固定自动备份、RPO 声明和恢复密钥模型。
>
> 关联规则/里程碑：M6、ADR-0002、ADR-0008、ADR-0010

## 背景

LedgerKit 的活库只位于 OS 本地应用数据目录。它可以承受进程崩溃，却不能单独应对整台设备丢失。自动备份还必须同时解决三个问题：同步目录短暂失效不能被误报为成功；用户遗失恢复密码时不能假装存在后门；保留无限历史会增加隐私暴露和管理成本。

## 决策驱动因素

- 设备丢失状态必须来自可验证事实，而不是仅凭“配置过目录”
- 便携备份不依赖原设备密钥存储即可跨设备恢复
- 密码和派生密钥不落盘、不进日志、不进诊断
- 自动备份失败持续可见，保留策略确定且可测试
- 正常退出和升级前仍有本机可恢复点

## 方案

### 方案 A：永久保存恢复密码或设备密钥

可以在每次启动后无交互运行外部备份，但会把便携包的唯一恢复秘密绑定到或暴露在本设备，扩大凭据生命周期和实现面。

### 方案 B：用户密码只在进程会话中解锁

首次选择外部目录时先创建并验证一个加密包；密码只保存在可清零的进程内存中。重新启动后状态为 locked，用户再次创建备份即可解锁本次会话。遗失密码不可恢复。

### 方案 C：无密码自动备份

同步目录泄露会直接暴露私人账本，违反 ADR-0008，拒绝。

## 决策

接受方案 B，并固定以下规则：

1. 用户选择外部目录并成功创建、重新解密和验证首个 `ledgerkit-portable-backup/v1` 包后，才保存该目录配置并把本次会话标记为 unlocked。密码仅存于 `Zeroizing<String>` 进程内存；不写数据库、设置、日志、诊断或包 header。应用重启后恢复为 locked。遗失密码没有应用后门。
2. 应用活跃且会话已解锁时，每个本地日历日至多创建一组新的外部每日备份；正常退出也检查是否到期。每日包默认保留最近 7 个。每个自然周由已验证每日包派生一个字节一致的周备份，保留最近 4 个。
3. 正常退出另在 OS 本地应用数据目录创建一致性 SQLite 快照并保留最近 7 个；schema migration 和 restore 前也必须创建可打开的一致性快照。这些同设备快照不构成设备丢失保护。
4. 只有同时满足以下条件才能显示“设备丢失受保护／RPO ≤ 24 小时”：外部目录已配置；最近一次外部包创建后已重新认证、校验哈希并打开数据库验证；成功时间不早于当前 UTC 24 小时；成功后的最近尝试没有失败。其他情况一律显示未受保护、pending 或 failed。
5. 目录离线、磁盘/同步冲突、写入、验证或轮换失败会持久化最近尝试时间与稳定错误类别，并立即撤销受保护声明。恢复成功后清除来自旧设备的外部目录配置，必须由用户在新设备重新选择。
6. 保留轮换只匹配 LedgerKit 自己生成的 `ledgerkit-daily-*` 和 `ledgerkit-weekly-*` 文件，不删除用户的手动备份或其他文件。发布前写临时文件、同步落盘并原子重命名；已存在目标视为冲突，不覆盖。

## 后果

- 正面影响：RPO 声明可审计；外部包泄露不暴露明文；新设备只需包和独立保存的密码即可恢复。
- 负面影响：重启后自动外部备份保持 locked，直到用户再次输入密码；遗失密码不可恢复；同设备退出快照不抵御整机丢失。
- 数据迁移影响：升级和迁移备份仍使用一致性 SQLite 快照；对外便携格式继续由 ADR-0008 约束。
- 测试与运维影响：必须覆盖过期、最近失败、目录失效、轮换、随机性、恢复前快照和恢复后重配置。

## 反转条件

若 P1 引入经过威胁建模的 Windows Credential Manager 便利副本、多设备密钥同步或用户可导出的恢复密钥，应创建新 ADR。便利存储不得成为便携包唯一秘密，也不得静默改变已有包的 KDF/AEAD 格式。保留数量或 RPO 条件改变同样需要版本化决策与迁移说明。

## 验证

- 脱敏 fixture：程序生成的空账本与合成恶意公式文本
- 自动化测试：随机 salt/nonce、错误密码、篡改/截断/未知格式与 KDF、目录失效后持续告警、7/4 保留、隐私诊断
- 性能/体积/恢复验证：完整创建、验证和恢复必须低于 10 分钟；任务 14 记录 Windows x64 包体变化
- 对账或差异桥：恢复前后 ledger ID、事件水位、canonical posting hash 和 schema 一致
