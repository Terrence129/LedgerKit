# ADR-0002：模块化单体与本地 SQLite 数据位置

> 状态：Accepted
>
> 日期：2026-09-02
>
> 决策者：项目所有者
>
> 授权：项目所有者在 M0 实现提示中明确接受本决策方向，并授权本 ADR 直接设为 Accepted。
>
> 关联规则/里程碑：M0、EVT-004、EVT-005、MIG-002

## 背景

LedgerKit 是单用户、本地优先的个人财务桌面应用。财务写入、迁移切换、备份恢复和离线能力要求应用只有一个权威账本，且不能把 WebView、同步盘或远程服务变成第二事实源。本 ADR 不决定 Tauri 或 Avalonia；该选择保留给 ADR-0001 的 M1 门禁。

## 决策驱动因素

- 财务写入的原子性、可恢复性与单一权威来源
- 核心功能断网可用和真实数据默认不离开设备
- 单人长期维护、安装体积与进程树预算
- 同步盘锁冲突、部分同步和网络数据库故障风险

## 方案

### 方案 A：模块化单体和本地 SQLite 活库

一个桌面应用进程树包含表现层、Application、Domain/Core 和基础设施适配器。每个账本同一时刻只有一个活跃的权威 SQLite 数据库，由 Core 独占访问。活库放操作系统本地应用数据目录；用户选择的同步盘或网络位置只接收已关闭并验证的一致性备份包。

### 方案 B：本地或云端服务加远程数据库

可以跨设备并发访问，但引入登录、网络、部署、协议兼容、安全运维和第二故障域，超出 1.0 产品边界。

### 方案 C：直接在同步盘运行 SQLite 活库

文件看似易于同步，但锁、WAL、多文件原子性和冲突副本不受同步服务保证，可能损坏或分叉权威数据。

## 决策

接受方案 A，并固定以下边界：

- 1.0 是单应用模块化单体；不建立微服务、本地 HTTP 服务、Node/Python sidecar、后台 daemon 或远程数据库。
- 一个打开的账本只有一个活跃权威 SQLite 文件。staging、候选迁移库和备份均不是并行事实源。
- 活库必须位于平台适配器解析出的本地应用数据目录，禁止直接在 OneDrive、Dropbox、NAS 或网络盘运行。
- 只有权威 Core 能访问数据库。UI 只能调用具名高层业务命令或只读查询，不能获得任意 SQL、posting、shell 或不受限路径能力。
- 迁移、恢复和 schema upgrade 必须先在候选或临时位置完成验证，再原子切换；任何失败保留原活库。
- 同步盘可作为用户明确选择的备份目标，但备份必须来自 SQLite 一致性快照或已关闭副本并完成完整性验证。

## 后果

- 正面影响：事实源、事务边界、权限边界和恢复路径清晰；核心功能完全离线。
- 负面影响：1.0 不提供实时多设备协作；跨设备依赖显式备份/恢复或导出。
- 数据迁移影响：导入只能提交到新候选库并在对账、备份验证后切换。
- 测试与运维影响：必须测试路径隔离、单写者、崩溃恢复、同步盘拒绝和原子切换失败路径。

## 反转条件

只有项目范围明确加入多用户并发或实时跨设备同步，且项目所有者接受新的威胁模型、服务运维和迁移成本时才重新评估。反转需要新的 Accepted ADR、远程协议、冲突模型、端到端加密与本地数据迁移方案。
