# ADR-0006：已过账事件的修订与冲正语义

> 状态：Accepted
>
> 日期：2026-09-02
>
> 决策者：项目所有者
>
> 授权：项目所有者在 M0 实现提示中明确接受已过账事件只能修订或冲正，并授权本 ADR 直接设为 Accepted。
>
> 关联规则/里程碑：M0、EVT-001、EVT-002、EVT-005

## 背景

原地覆盖或物理删除已过账事件会破坏审计、旧导出复现、迁移对账和投影重建。与此同时，普通数据录入错误、撤销交易和商户退款是不同业务语义，不能混为一谈。

## 决策驱动因素

- 历史可追踪且当前结果可确定性计算
- 修订、冲正、退款和报销语义分离
- 旧 watermark/版本的导出可以复现
- 失败或并发操作不会产生半条修订链

## 方案

### 方案 A：追加修订/冲正事件

保留旧事件，以显式引用、理由和新 posting 表达更正；查询在给定 watermark 解析有效链。

### 方案 B：更新或删除原事件

当前表面简单，但无法复现过去结果，审计和同步导出会产生无解释变化。

## 决策

接受方案 A：

- 已过账事件的财务字段、类型明细、posting 和冻结的 FX resolution 不得原地覆盖或物理删除。
- 修订创建完整的新事件，必须包含 `supersedes_event_id`、非空理由、新 `revision` 和完整替代内容。原事件继续存在；在指定 event watermark 下，每条修订链只有最新有效叶节点参与当前业务查询和投影。
- 修订允许改变有效日和财务内容，因此当前 watermark 下的历史期间可能变化；UI 必须预览受影响期间。旧 watermark、policy 和 calculation version 仍解析旧叶节点并可复现旧导出。
- 冲正创建新事件，必须包含 `reverses_event_id`、理由和由 Core 生成的逐 posting 精确相反影响。原事件和冲正事件均保留，成对后的净财务影响为零；同一有效事件只能被一个有效冲正链抵销。
- 对修订过的事件执行冲正时，目标是当前有效叶节点；对已冲正事件再修订必须先以新的业务事件表达，不能复活旧记录。
- 修订或冲正在业务事件、引用、posting、审计和投影水位的同一 transaction 中提交；任一校验失败全部回滚。
- 商户退款和报销是新的收入类业务事件并使用稳定 `refund` / `reimbursement` semantic role，不设置 `reverses_event_id`，默认不抵扣原消费分类。
- 支出查询只计当前 watermark 下有效、未被冲正的消费贡献；冲正对不计消费笔数，退款/报销按自身有效日单列。

稳定错误包括 `POSTED_EVENT_IMMUTABLE`、`REVISION_REASON_REQUIRED`、`REVISION_TARGET_NOT_EFFECTIVE`、`REVERSAL_REASON_REQUIRED`、`EVENT_ALREADY_REVERSED` 和 `REVISION_CHAIN_CYCLE`。

## 后果

- 正面影响：当前结果、历史版本和更正原因都可解释；投影可从追加事实重建。
- 负面影响：查询必须解析有效链，修订影响范围需要预览和局部重放。
- 数据迁移影响：源更正应导入成明确版本或问题清单，不能覆盖已提交事件。
- 测试与运维影响：必须覆盖链、循环、重复冲正、跨期修订、事务失败、旧 watermark 复现和冲正净零。

## 反转条件

无条件允许原地覆盖不在可接受范围。若未来增加草稿，只有尚未过账且从未产生权威 posting 的草稿可编辑或删除，必须由新 ADR 明确状态转换。

## 验证

- 脱敏 fixture：`17-reversal-zero-net/`、`29-revision-watermark/`
- 自动化测试：有效链解析、posting 反向、幂等保护、循环检测和投影重建
- 性能/体积/恢复验证：长修订链查询与局部重放基准
- 对账或差异桥：旧/新 watermark 的 canonical hash 和受影响期间清单
