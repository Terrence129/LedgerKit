# LedgerKit Beta 导入指南

LedgerKit `1.0.0-beta.1` 的公开导入器只接受版本化、规范化的 `.xlsx` 契约。它不是对任意私人表格的猜测式导入器。真实 v1.3.0 工作簿需要在仓库外只读转换为该契约，转换副本、映射和对账结果始终保留在本机私有工作区。

## 安全边界

- 原始 Excel 永不修改；先复制，再由桌面 Excel 全量重算并保存副本。
- 文件选择器只把路径交给 Rust Core；WebView 请求不能携带任意路径或 SQL。
- 分析先进入 staging。零 blocker、零对账差异、用户确认前，不创建或替换正式账本。
- 宏、外部链接、未知/缺失工作表、表头漂移、超限大小/行列/单元格和公式缓存缺失都会被拒绝。
- 不把真实工作簿、数据库、导出、逐笔数据、私人路径或截图附到公开 issue 或提交。

## 规范化工作簿

全量契约固定 15 张精确命名工作表；包括设置、机构、账户、分类、汇率、现金事件、调拨、换汇、组合、证券、价格、投资事件、期初基线、检查与支出分析证据。模板最大 5 MiB、总计最多 20,000 行、每表最多 32 列、文本单元格最多 4,096 字符。

公式只作为证据保存。财务输入公式必须带可用缓存；派生、状态和展示公式不得成为权威金额。相同字节文件重复分析必须得到相同映射和 reconciliation hash。

## Dry-run

1. 在尚无活库的首次设置页选择工作簿。
2. 审阅文件哈希、模板/导入器/目标 schema 版本、逐表行数和旧 ID 到新 ID 映射。
3. 按账户、组合和标的确认完整历史或明确 cut-over；不确定时停止，不能猜测。
4. 处理问题清单，核对现金原币余额、持仓数量、剩余成本、已实现盈亏、净股息、独立费用、净资产、估值证据和支出分桶。
5. 只有 blocker 为零且所有差异为零时，才能勾选确认并提交该 opaque batch ID。

## 提交、验证与回退

提交在新的候选数据库中重放 Core 规则、重建投影并复核；随后创建并验证备份，再以同卷原子 rename 切换。不同文件哈希不会合并到已经过账的账本。任何失败保留旧账本；修正后的工作簿作为新候选重新分析。

实际 v1.3.0 迁移、逐账户/组合策略和最终 cut-over 的完整操作顺序见 [`operations/migration.md`](operations/migration.md)。最终切换前必须另建并验证密码加密便携备份；本机临时快照不能替代设备外保护。
