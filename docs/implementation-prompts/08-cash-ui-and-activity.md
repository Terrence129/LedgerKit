# 任务 08/14：日常录入、活动时间线与更正 UI

你正在执行 LedgerKit 的现金日常录入和活动 UI。遵循共同执行协议，确认现金 Core/黄金测试已在 `main`，创建分支 `phase/m2-cash-ui`。

## 必读材料

- 开发计划书的信息架构、日常录入、更正和可访问性章节
- 现金相关 Accepted ADR 与 Domain 错误契约
- `AGENTS.md` 中 UI、权限和隐私边界

## 实现

1. 建立五个顶级入口的稳定应用壳；本阶段完整交付“活动”的现金部分，不提前实现支出分析页面。
2. 全局新增：收入、支出、调整、同币种调拨、换汇。
3. 表单调用 `preview_event` 获取权威影响预览；前端即时校验只改善体验，保存仍由 Core 重新校验。
4. 预览显示原币现金变化、使用的 FX、手续费、分类、数据完整性和阻断错误。
5. 活动时间线实现日期、类型、账户、分类和搜索筛选，以及有上限的游标分页。
6. 事件详情显示业务内容、posting 摘要、FxResolution、revision/reversal 链和脱敏 audit 元数据。
7. 修订/冲正前展示权威影响，成功后刷新投影并保持旧版本可追踪。
8. 防止重复提交；请求进行中禁用重复操作；取消、超时或 Domain 失败不能显示伪成功状态。
9. 所有录入、详情和更正支持键盘；错误定位首个字段；状态不只依赖颜色；支持窄屏和 200% 缩放。

## 测试与验收

- 熟练路径下普通收支录入目标 ≤15 秒。
- 收入、支出、调整、调拨、换汇和换汇手续费 E2E。
- Core 拒绝前端伪造币种、符号、FX、posting 或事件状态。
- 修订/冲正后时间线、详情、余额和版本链一致。
- 分页、筛选、返回状态和失败恢复。
- 断网录入和默认零网络请求。
- 键盘、焦点、标签、live region 和高对比检查。

不得引入图表库、第二状态框架或前端财务计算。通过后提交、合并并推送 `main`。
