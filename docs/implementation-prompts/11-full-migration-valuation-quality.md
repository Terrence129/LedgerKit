# 任务 11/14：全量迁移、Cut-over、估值与数据质量 Core

你正在执行 LedgerKit 的全量 Excel 迁移、两种 cut-over、估值和数据质量后端。遵循共同执行协议，确认投资纵切已在 `main`，创建分支 `phase/m5-full-migration-valuation`。

## 必读材料

- `docs/operations/migration.md`
- ADR-0011、0012、0014
- MIG、INV、VAL、EXP 规则和完整迁移黄金 fixture
- 开发计划书第 7、13–15 节

禁止读取真实 Excel；所有开发和自动测试使用合成 fixture。

## 实现

1. Importer 补齐组合、证券、价格、买卖、股息、费用、持仓对账基线、检查页和支出分析参考输出。
2. 实现完整历史重建模式：完整事件和现金腿闭环，避免期初余额重复计入。
3. 实现显式 cut-over：OpeningBalance、OpeningPosition、OpeningPerformance；保留零持仓历史头寸和 `instrument_id=null` 的组合级费用。
4. 每个受影响账户/组合必须显式选择策略；没有选择或任一关键差异无法解释时阻断提交。
5. 同一证券事件的现金腿与数量腿共同处理，禁止拆分。
6. 对账矩阵覆盖源行、映射、逐事件现金/数量腿、账户原币余额、持仓数量/成本、已实现盈亏、净股息、费用、机构、币种和总净资产。
7. 生成 Excel 可见口径与应用规范口径的逐事件/逐桶差异桥，不能用宽泛容差隐藏差异。
8. 实现 ValuationSnapshot/Line：估值日、价格修订、FxResolution、原币值、本位币值、未估值原因、计算版本和水位。已确认快照不可覆盖。
9. 实现 `get_overview` 后端：估值日、已估值净资产、未估值集合、机构/币种/现金/持仓构成、截至估值日 MTD 和异常摘要。
10. 实现 `get_data_quality` 后端：缺 FX、缺价格、陈旧价格、负持仓、映射、重复和导入问题，返回稳定修复上下文与状态。
11. 启动时发现投影版本/水位不匹配，必须先标记不可用并重建；不得混合不同计算版本显示。

## 测试与验收

- 完整历史和显式 cut-over 两套端到端 fixture。
- 期初日前、当日和之后事件；停用账户历史；零持仓历史业绩；组合级费用。
- 估值日向前/向后、月中 MTD、未来值排除、缺失和陈旧数据。
- Excel 与规范口径所有差异可定位解释。
- 候选数据库验证失败不切换活库。
- 清空重建后账户、持仓、净资产、快照和质量结果完全一致。

通过后提交、合并并推送 `main`。
