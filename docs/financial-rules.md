# Financial Rules

> 状态：M0 Accepted 基线
>
> 规则来源：开发计划书、Excel 调查结论及后续 Accepted ADR
>
> Decimal、证券成本、修订/冲正、迁移、市场数据和支出规则已经 M0 Accepted ADR 固化；仍未 Accepted 的主题不得由本文推断。

本文把高频财务约束压缩为可引用的规则 ID。详细理由、迁移差异和边界案例仍以开发计划书、Accepted ADR 与黄金样例为准。

## 数值与日期

- `NUM-001`：金额、数量、单价、汇率、成本和盈亏的权威计算不得使用二进制浮点；Domain 使用受约束 Decimal 或 `{coefficient, scale}`。SQLite 源事实与权威审计值使用规范十进制 `TEXT`，禁止 `REAL`。
- `NUM-002`：任一权威 Decimal 最多 28 位有效数字。普通金额输入最多 8 位小数、证券数量 12 位、单价 12 位、汇率 15 位、内部成本/换算结果 18 位；违反合约必须返回 ADR-0004 定义的稳定错误。
- `NUM-003`：保留源十进制文本及 scale；超出用途 scale、超出币种常用精度或溢出时不得静默截断。币种常用精度超限但仍在金额 scale 内时必须显式确认。
- `NUM-004`：唯一默认 midpoint 舍入模式为 `half-up`。只在明确的内部成本/换算、posting、投影或显示边界舍入；普通解析、事件保存和加减不得提前舍入。fixture metadata 必须记录实际边界。
- `NUM-005`：IPC、JSON fixture 和导入导出中的财务数字使用禁止指数、前导 `+`、无意义前导零和负零的十进制字符串；有意义的尾随零保留源 scale。
- `NUM-006`：禁止用宽泛总额容差掩盖逐笔差异；同一输入和算法的内部结果必须精确一致。统一 scale 的定标整数只能是可重建投影并必须检查溢出。
- `DATE-001`：财务有效日是本地日历日期；创建/修改时间使用 UTC 时间戳。
- `DATE-002`：日期范围含首尾；概览 MTD 的截止日与估值日一致。
- `DATE-003`：同日证券交易必须有稳定 sequence；导入默认使用源行顺序作为初始 sequence。

## 本位币、汇率与估值

- `FX-001`：汇率方向统一为“1 单位原币 = 本位币”；本位币对自身汇率恒为 1。
- `FX-002`：自动汇率只能选择目标日期当日或此前最大日期的正数 active 修订；禁止未来值，结果不得依赖物理行顺序。
- `FX-003`：人工覆盖必须保留自动候选、覆盖值、原因、最终值和计算版本。
- `FX-004`：交易/手续费按事件有效日折算；资产估值按估值日选择价格与汇率，估值汇率不改用价格日期。
- `FX-005`：缺少必要汇率时项目进入未折算集合，禁止按零或 1:1 处理。
- `VAL-001`：价格只能选择估值日当日或此前最大日期的正数 active 修订；缺价格时资产未估值。
- `VAL-002`：已估值净资产只包含可完整估值项目；未估值项目必须单列并可定位修复。
- `VAL-003`：净资产 = 现金账户估值 + 证券持仓市值；结算现金与持仓均为独立资产，不重复计算同一现金腿。
- `VAL-004`：普通估值动态使用当前 active 的 as-of 修订；已确认估值快照冻结所用价格/汇率修订、计算版本和源水位。历史交易冻结已过账 `FxResolution`，改变折算必须创建带理由的事件修订。

## 现金事件

- `CASH-001`：账户只有一个币种；现金变动币种必须等于账户币种。
- `CASH-002`：收入、支出和费用输入为正数，符号由事件类型派生；只有余额调整允许显式正负增量。
- `CASH-003`：同币种调拨要求两个不同账户、相同币种和相同金额；不计收入/支出，净现金变化为零。
- `CASH-004`：换汇要求两边币种不同；换汇本金不计收入/支出，手续费独立过账并按自身币种折算。
- `CASH-005`：期初现金由显式 OpeningBalance 事件表达；账户 `opened_on` 只是元数据，不参与余额公式。

## 投资

- `INV-001`：持仓键为 `(portfolio_id, instrument_id)`；同一标的跨组合不得合并成本、数量或收益。
- `INV-002`：BUY/SELL 才改变数量；DIVIDEND 和独立投资费用不得改变数量。
- `INV-003`：交易币种必须与标的交易币种和结算账户币种一致；覆盖组合默认结算账户必须记录原因。
- `INV-004`：买入费用进入持仓成本；卖出费用减少净卖出收入；二者不得再次计入独立投资费用。
- `INV-005`：独立投资费用减少结算现金并进入标的级或组合级投资净回报；组合级费用首版不自动摊派。
- `INV-006`：卖出不得超过当时可用持仓；1.0 不支持做空。
- `INV-007`：使用逐笔移动加权平均；卖出时锁定结转成本，全部卖清时结转全部剩余成本并使数量和 carrying cost 精确归零，后续重新买入不得继承残值或改变历史已实现盈亏。
- `INV-008`：投资总回报 = 已实现交易盈亏 + 净股息 - 独立投资费用 + 未实现盈亏；净股息扣除预扣税和股息手续费，本功能不宣称满足税务申报规则。

## 修订、分录与投影

- `EVT-001`：已过账事件的财务影响不得原地覆盖或物理删除；修订指向被替代事件，冲正指向被冲正事件。
- `EVT-002`：冲正完成后，原事件与冲正事件的净财务影响为零；商户退款/报销不是账务冲正。
- `EVT-003`：LedgerPosting 只能由权威 Domain 从业务事件确定性生成，不允许独立创建或修改。
- `EVT-004`：事件、posting、审计记录和投影水位更新必须在一个 SQLite transaction 中完成。
- `EVT-005`：投影可以删除并从源事件重建；相同事件水位和计算版本必须产生相同规范序列与哈希。
- `EVT-006`：修订是带理由、`supersedes_event_id` 和完整替代内容的新事件；给定水位只取修订链当前有效叶节点。冲正是带理由、`reverses_event_id` 和精确相反 posting 的新事件；成对净影响为零。

## 支出分析

- `EXP-001`：P0 期间支出 = 普通支出 + 普通手续费 + 换汇手续费。
- `EXP-002`：收入、调整、调拨本金、换汇本金、证券本金、买卖手续费、股息手续费/预扣税和独立投资费用不进入 P0 消费支出。
- `EXP-003`：每个已折算的 P0 支出贡献必须且只能进入一个用户分类或系统费用桶。
- `EXP-004`：完整时 `sum(bucket amounts) = total expense`；缺 FX 时 `sum(valued bucket amounts) = valued subtotal`。
- `EXP-005`：退款与报销使用稳定 semantic role，按自身有效日单列汇总，默认不冲减原消费分类。
- `EXP-006`：分类归档、改名或重排不得使历史金额消失或改变事件归属；系统费用桶不可删除。
- `EXP-007`：总笔数使用全局 distinct event；桶内笔数使用桶内 distinct event，桶笔数之和不要求等于总笔数。
- `EXP-008`：KPI、全部分桶、Top 10 + 其他、语义表格和下钻必须消费同一个权威查询结果。
- `EXP-009`：聚合结果不得携带无界事件 ID 列表；下钻使用规范化筛选上下文和分页活动查询，以满足响应体预算。
- `EXP-010`：已折算贡献恰好进入一个稳定桶：用户 `category_id`、`system:uncategorized`、`system:ordinary-fee` 或 `system:fx-fee`。系统桶不可删除或改 ID。
- `EXP-011`：正金额桶按 `amount DESC, bucket_id ASC` 稳定排名；Top 10 之外合并为 `system:top10-other`，完整 bucket rows 仍用于语义表格。
- `EXP-012`：权威查询结果记录解析日期、事件/主数据水位、`expense-policy-v1`、`expense-bucket-policy-v1`、`refund-policy-v1`、calculation version 和 `ledgerkit-canonical-json-v1` SHA-256。同一水位和版本的结果不得受 SQLite 物理行序或导入批次顺序影响。

## 迁移与数据安全

- `MIG-001`：原始 Excel 永不修改；先读取副本并记录哈希、导入器版本和 schema 版本。
- `MIG-002`：导入先进入 staging；每个问题可定位到工作表和行号，用户确认前不得写入正式账本。
- `MIG-003`：1.0 只支持一次性初始迁移；仅同一字节文件在相同导入器/schema 下要求幂等重跑，不把修改后的工作簿增量 merge 到已过账账本。
- `MIG-004`：期初现金、期初持仓和历史业绩必须显式桥接；不得同时过账 cut-over 前交易与已经包含其影响的期初值。
- `MIG-005`：同一证券事件的现金腿和数量腿不得拆分迁移。
- `MIG-006`：cut-over 没有安全默认值；未完成逐账户/组合闭环对账时禁止提交迁移。
- `MIG-007`：每个账户和组合必须显式选择 `full_history` 或 `explicit_cutover`。cut-over 前事件不生成 posting；期初现金、持仓、成本、已实现盈亏、净股息和标的/组合级费用必须由 Opening 事件完整桥接，包括零持仓历史头寸。

## 规则变更流程

1. 起草 ADR，说明当前规则、拟议变化、差异和反转条件。
2. 用脱敏 fixture 固定新旧预期和迁移桥。
3. 经用户确认后把 ADR 设为 Accepted。
4. 更新本文和黄金样例。
5. 实现并运行投影重建、迁移和财务回归测试。
